# Дизайн-спека: Фреймворк работы над веб-проектами (дизайн → фронтенд)

Дата: 2026-08-28. Статус: утверждено на словах, ожидает финального ревью.

## Проблема

Проекты с высокой неопределённостью: у заказчика нет контента, фирстиля, текстов.
Дизайнер выдумывает содержание на ходу → макет расходится с ожиданиями → длинный
цикл правок, дизайн разваливается. Причина: первым носителем «версии правды»
становится макет. Лечение: дешёвые артефакты для утверждения ДО макетов.

## Роли

- **Пользователь (Евгений, UX/UI-дизайнер):** принимает решения, ревьюит,
  работает руками только там, где нужна рука дизайнера — дизайн в Figma,
  концепты, ручные правки, генерация контента в syntx.ai.
- **Claude Code:** вся остальная работа — исследования, документы, тексты,
  структуры, промпты для генераций, прототипы, вся вёрстка, гит, деплой.

## Архитектура: «Пайплайн с артефактами»

Два уровня:

1. **База фреймворка** (эта папка) — правила, фазы, регламенты. Дорабатывается.
2. **Шаблон проекта** `_project-template/` — копируется в папку нового проекта.

### Структура базы

```
Фреймворк/
├── README.md              # как пользоваться, быстрый старт
├── CHANGELOG.md           # история доработок фреймворка
├── framework/
│   ├── 00-overview.md     # карта процесса, схема фаз
│   ├── 01-discovery.md    # бриф, исследование рынка, референсы
│   ├── 02-concept.md      # позиционирование, контент-карта, мудборд
│   ├── 03-design.md       # прототип → UI-кит → макеты (Figma)
│   ├── 04-frontend.md     # вёрстка, анимации, адаптив
│   ├── 05-release.md      # гит, хостинг, передача
│   ├── stack.md           # регламент выбора стека
│   ├── models.md          # модели ИИ по задачам + токен-экономия
│   ├── content-gen.md     # сессия «Контент-промптер»: промпты для syntx.ai
│   └── lessons.md         # накопленные уроки (пишет ретро)
├── docs/specs/            # спеки и планы самого фреймворка
└── _project-template/
    ├── CLAUDE.md          # правила проекта, автоматически читается сессиями
    ├── PROJECT.md         # паспорт: статусы фаз, ключевые решения, ссылки
    ├── 00-docs/
    │   ├── brief.md       # шаблон брифа с вопросами заказчику
    │   ├── research.md    # анализ рынка/конкурентов
    │   ├── content-map.md # структура страниц + черновые тексты
    │   └── decisions.md   # журнал решений и допущений
    ├── 01-concept/        # мудборд, референсы, направление
    ├── 02-design/         # ui-kit.md, ссылки на Figma
    ├── 03-code/           # вёрстка
    └── assets/            # контент заказчика, генерации syntx.ai
```

### Ключевая механика

- Любая сессия стартует с чтения `CLAUDE.md` + `PROJECT.md` — состояние проекта
  живёт в файлах, не в памяти чатов. Это же — главная токен-экономия.
- Каждая фаза: вход → выход (файлы-артефакты) → мягкий гейт.
- **Мягкий гейт:** артефакт показан заказчику; молчит — фиксируем допущения
  в `decisions.md` и едем дальше.

## Гибкость: разбор

Первая сессия проекта — разбор (~5 вопросов: тип проекта, что есть у заказчика,
сроки). Итог — разметка фаз в `PROJECT.md`: `нужна / упрощённая / пропустить`.
Пропуск фазы = строка с причиной в `decisions.md`.

## Обучаемость

1. **Ретро-сессия** после проекта (~15 мин) → уроки в `framework/lessons.md`,
   правки шаблонов, запись в `CHANGELOG.md`.
2. **Правило двух повторов:** проблема повторилась в двух проектах →
   обязательная правка фреймворка.
3. `lessons.md` наследуется новыми проектами.

## Сессии

Разбор → Discovery → Концепция → Прототип → UI-кит → Макеты → Вёрстка →
Адаптив/анимации → Релиз → Ретро. Плюс сквозная сессия **Контент-промптер**
(вызывается на любом этапе): Claude пишет промпты для syntx.ai под конкретные
слоты макета — формат, стиль проекта, референсы, негативные промпты; результат
кладётся в `assets/`.

Для каждой сессии в файле фазы — готовый стартовый промпт (копипаст).
После сборки базы — 3–4 кастомных скилла: `/новый-проект`, `/статус`, `/ретро`.

## Регламент стека (stack.md)

- **Лендинг/промо** → HTML + CSS + JS + GSAP, статик-хостинг/GitHub Pages.
- **Корпсайт/многостраничник** → Astro, деплой Netlify/Vercel.
- **E-commerce:** витрина без корзины → Astro; полноценный магазин → Next.js.
  Решается на разборе.

## Модели и токены (models.md)

- **Opus** — думающие этапы: разбор, исследование, концепция, архитектура, дебаг.
- **Sonnet** — рабочая лошадка: вёрстка по плану, адаптив, документы по шаблону.
- **Haiku** — механика и рутина.
- **syntx.ai** — весь фото/видео/иллюстративный контент; шпаргалка моделей
  внутри syntx — в `content-gen.md`.
- Правила: состояние в файлах; новая фаза = новая сессия; в контекст — только
  нужные файлы.

## Дополнительно

- Визуальный Artifact-гайд — карта процесса одной страницей (после сборки базы).
- Язык всех материалов — русский.

## Критерии успеха

1. Новый проект стартует копированием `_project-template/` без доп. настройки.
2. Любая сессия восстанавливает контекст из файлов за один прочит.
3. Правки заказчика ловятся на уровне текстов/структуры, а не готовых макетов.
4. Фреймворк дорабатывается по итогам ретро без переделки основания.
