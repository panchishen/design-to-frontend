# План сборки фреймворка

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Контентный проект — вместо тестов шаги проверки согласованности.

**Goal:** Собрать базу фреймворка и копируемый шаблон проекта по спеке `docs/specs/2026-08-28-framework-design.md`.

**Architecture:** Markdown-база из 2 уровней: `framework/` (правила и фазы) + `_project-template/` (копируется в проект). Все файлы на русском.

**Tech Stack:** Markdown. Без кода.

## Global Constraints

- Язык: русский, кратко, без «воды».
- Каждый файл фазы обязан содержать разделы: Цель / Вход / Выход (артефакты) / Шаги / Гейт (чек-лист) / Когда пропускать / Стартовый промпт сессии (в код-блоке, копипаст).
- Разделение ролей в каждой фазе: что делает Claude, что делает дизайнер.
- Стартовые промпты всегда начинаются с «Прочитай CLAUDE.md и PROJECT.md».
- Имена файлов и структура — строго по спеке.
- Никаких TBD/TODO — всё содержимое финальное.

### Task 1: Файлы фаз — framework/00–02

**Files:** Create: `framework/00-overview.md`, `framework/01-discovery.md`, `framework/02-concept.md`

- [ ] `00-overview.md`: философия («правда живёт в артефактах, не в макете»), схема пайплайна (текстовая диаграмма фаз с артефактами), таблица «фаза → сессия → артефакты → модель», принцип мягких гейтов, принцип разбора.
- [ ] `01-discovery.md`: разбор (5 вопросов, разметка фаз в PROJECT.md) + бриф (структура вопросов заказчику по блокам: бизнес, аудитория, конкуренты, контент, вкусы/антивкусы) + исследование рынка (методика: конкуренты, референсы, паттерны ниши; выход — research.md). Промпты для сессий «Разбор» и «Исследование».
- [ ] `02-concept.md`: позиционирование и tone of voice; контент-карта (структура страниц + черновые тексты — главное лекарство от правок); мудборд/направление (2–3 направления на выбор заказчику; Claude собирает HTML-мудборд или список референсов, дизайнер курирует). Промпт сессии «Концепция».

### Task 2: Файлы фаз — framework/03–05

**Files:** Create: `framework/03-design.md`, `framework/04-frontend.md`, `framework/05-release.md`

- [ ] `03-design.md`: прототип (текстовый wireframe от Claude → низкодетальный прототип в Figma), UI-кит (токены: цвет, типографика, сетка, компоненты; фиксация в `02-design/ui-kit.md`), макеты в Figma (роль Figma MCP: генерация основы, синхронизация), правило «правки смыслов — в content-map, правки визуала — в макете». Промпты сессий «Прототип», «UI-кит», «Макеты».
- [ ] `04-frontend.md`: порядок вёрстки (десктоп → адаптив → анимации), критерии приёмки (пиксельная точность к макету, Lighthouse, кроссбраузерность), процесс ревью дизайнером через превью, итерации правок. Промпты сессий «Вёрстка», «Адаптив/анимации».
- [ ] `05-release.md`: чек-лист перед релизом (метатеги, favicon, 404, формы, аналитика), git-процесс (Claude ведёт), деплой по типам хостинга, передача заказчику. Промпт сессии «Релиз» + промпт сессии «Ретро» (выход — записи в lessons.md и CHANGELOG.md).

### Task 3: Регламенты — stack, models, content-gen, lessons

**Files:** Create: `framework/stack.md`, `framework/models.md`, `framework/content-gen.md`, `framework/lessons.md`

- [ ] `stack.md`: таблица решений (тип проекта → стек → хостинг → когда отступать), правила по умолчанию из спеки, критерии выбора на разборе.
- [ ] `models.md`: таблица «задача → модель → почему», токен-правила (состояние в файлах, сессия = фаза, точечный контекст), приёмы экономии в Claude Code.
- [ ] `content-gen.md`: сессия «Контент-промптер» — воркфлоу (слот в макете → бриф слота → промпт для syntx.ai), структура промпта для фото/видео (объект, стиль, свет, композиция, формат/соотношение, негатив), таблица «тип контента → рекомендуемая модель в syntx.ai», правила консистентности серии изображений, куда класть результат (`assets/`).
- [ ] `lessons.md`: заголовок + формат записи урока (дата, проект, проблема, решение, что изменили) + 0 записей.
