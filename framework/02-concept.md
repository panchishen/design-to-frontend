# Фаза 2. Концепция

## Цель

Зафиксировать смыслы и направление ДО открытия Figma. Главный артефакт —
контент-карта с черновыми текстами: именно она лечит проблему «заказчик правит
смыслы в макете». Второй результат — утверждённое визуальное направление.

## Вход

- `brief.md` и `research.md` заполнены (фаза Исследование пройдена).

## Выход (артефакты)

- `00-docs/content-map.md` — структура страниц + черновые тексты всех блоков.
- `01-concept/` — мудборд / визуальные направления, выбранное направление.
- Позиционирование и tone of voice — раздел в `content-map.md`.

---

## Сессия «Концепция»

Роли: Claude пишет позиционирование, контент-карту и собирает направления.
Дизайнер курирует, выбирает направление, показывает заказчику.

### Шаг 1. Позиционирование и tone of voice

Claude на основе брифа и исследования формулирует (в начало `content-map.md`):

- **Оффер:** одна фраза — что, для кого, почему у нас (это будущий первый экран).
- **3–5 ключевых преимуществ** с доказательствами (не «качественно и недорого»,
  а конкретика из брифа).
- **Tone of voice:** как говорим с аудиторией (на «ты»/«вы», серьёзно/тепло,
  экспертно/просто) + 2–3 примера фраз.

### Шаг 2. Контент-карта

Для каждой страницы — список блоков сверху вниз. Для каждого блока:

- **Задача блока** — зачем он, что должен понять/сделать посетитель.
- **Черновой текст** — заголовок, подзаголовок, основной текст, CTA. Настоящие
  тексты, не рыба! Написаны Claude на основе брифа, помечены `[допущение]` там,
  где не хватило данных от заказчика.
- **Контент-слоты** — какие нужны фото/видео/иллюстрации: что изображено, откуда
  возьмём (заказчик / syntx.ai / стоки). Это заготовка для сессии Контент-промптер.

### Шаг 3. Визуальные направления

Claude готовит **2–3 направления** на выбор. Формат — HTML-мудборд (один файл в
`01-concept/`): для каждого направления — название-настроение, палитра, типографика,
3–5 референсов из research.md, короткое описание «почему подходит этому бизнесу».
Дизайнер выбирает и при желании дорабатывает. Выбор фиксируется в `PROJECT.md`.

### Шаг 4. Мягкий гейт — самый важный во всём пайплайне

Заказчику отправляются: оффер + контент-карта (можно как простой документ) +
выбранное направление. Формулировка для заказчика: «Проверьте, всё ли верно по
смыслу — тексты черновые, но структура и посылы будут именно такими».
Молчит — допущения в `decisions.md`, идём в Дизайн.

### Стартовый промпт

```
Прочитай CLAUDE.md, PROJECT.md, 00-docs/brief.md и 00-docs/research.md.
Сессия «Концепция» по framework/02-concept.md:
1) Сформулируй позиционирование, оффер и tone of voice.
2) Собери 00-docs/content-map.md: все страницы, блоки, черновые тексты
   (настоящие, не рыба; пробелы помечай [допущение]) и контент-слоты.
3) Подготовь 2–3 визуальных направления HTML-мудбордом в 01-concept/
   на основе референсов из research.md.
4) Дай выжимку для отправки заказчику.
```

---

## Гейт фазы (чек-лист)

- [ ] Оффер и tone of voice сформулированы.
- [ ] `content-map.md`: все страницы, все блоки, черновые тексты, контент-слоты.
- [ ] Допущения в текстах помечены и продублированы в `decisions.md`.
- [ ] Направление выбрано (дизайнером) и зафиксировано в `PROJECT.md`.
- [ ] Выжимка отправлена заказчику.

## Когда пропускать / упрощать

- **Есть фирстиль** → Шаг 3 сжимается: направление одно, строится вокруг фирстиля,
  мудборд — способ показать, как фирстиль превращается в веб.
- **Есть готовые тексты** → Шаг 2 превращается в раскладку текстов по блокам
  и проверку пробелов.
- **Пропустить фазу целиком** можно только для проектов «повтори как там» с полным
  контентом — причина в `decisions.md`.
