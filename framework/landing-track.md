# Трек «Лендинг на шаблоне»

Короткий трек вместо полного цикла (концепция → прототип → макеты), когда лендинг
собирается на готовом шаблоне и наполняется контентом заказчика.

**Шаблон:** пока `landing-template` не выделен — проект Dental AI
(`https://github.com/panchishen/dental-ai`; нет локальной копии — `gh repo clone panchishen/dental-ai`).
После выделения — репозиторий-шаблон `landing-template` («Use this template»).

**Запуск фаз:** одна фаза = одна сессия Claude Code, открытая в папке проекта.
Команда `/landing-next` сама находит следующую фазу по `PROJECT.md` и ведёт её.
В конце фазы Claude ставит статус «готово» и создаёт плашку «Запустить фазу N».

## Структура проекта

```
<Проект>/                  ← папка проекта, сессии запускаются отсюда
  PROJECT.md  CLAUDE.md    ← паспорт и правила (из _project-template)
  00-docs/                 ← brief, content-map, decisions (не публикуются)
  assets/prompts.md        ← промпты для syntx.ai
  assets/raw/<slot-id>/    ← исходники генераций и материалы заказчика
  Лендинг/                 ← git-репозиторий сайта (публичный), site/ = сайт
```

Документы проекта лежат **вне** репозитория: репозиторий публичный.

### 0. Старт

1. Скопировать из шаблона в `<Проект>/Лендинг/`: `site/` (ассеты — как временные
   заглушки), `claude-design-tokens/`, `serve-site.js`, `_typograf-site.js`,
   `.github/workflows/pages.yml`, `.gitignore`, `.claude/launch.json` (только сервер сайта).
   Не копировать исходники фото/видео, документы и архивы шаблона.
2. `git init`, первый коммит, `core.autocrlf false` (файлы в LF).
3. `gh repo create <аккаунт>/<имя>-landing --public` (аккаунт GitHub дизайнера), пуш, Pages через workflow
   (`gh api -X POST repos/.../pages -f build_type=workflow`).
4. **noindex:** в `<head>` каждой HTML-страницы — строка
   `<!-- PREVIEW-NOINDEX: удалить эту строку при публикации на боевом домене --><meta name="robots" content="noindex, nofollow">`.
   Workflow проверяет её наличие и не деплоит страницу без неё.
5. README: раздел «Для разработчика» (заливать только последний релиз; как снять
   noindex), превью, как выпускается релиз.
6. В корне проекта — `_project-template/`, таблица фаз этого трека в `PROJECT.md`,
   ссылки на репозиторий и превью.

**Выход:** ссылка на превью `https://<аккаунт>.github.io/<имя>-landing/`.

### 1. Разбор и аудит источников

1. Спросить, откуда брать материалы: сайт заказчика, папка, соцсети, переписка.
2. Аудит источников: тексты, услуги, цены, врачи/сотрудники, отзывы, контакты,
   реквизиты и лицензии, фото/видео (что годится по качеству, что нет).
3. Список блоков шаблона (по `site/index.html`) → `00-docs/content-map.md`: по каждому
   блоку — тексты (из источника / адаптировать / нет данных) и **таблица слотов**:

   | slot-id | Файл в `site/assets/` | Что изображено | Формат, px | Источник | Статус |
   |---|---|---|---|---|---|

   Источник: заказчик / syntx.ai (фото — Nano Banana, видео — Kling) / спросить.
   Имя файла и размер слота фиксируются здесь и дальше не меняются —
   на этом держится обновление контента без Claude (замена файла с тем же именем).
4. Бриф айдентики (`00-docs/brief.md`) — вопросы дизайнеру по одному:
   фирменные цвета (HEX или откуда снять), логотип (файл, вектор?), шрифты,
   брендбук, стиль фото (люди реальные или сгенерированные, интерьер реальный?),
   что нельзя показывать, юридические требования ниши.
5. Решить опциональные фазы 4 и 5 (нужна / пропущена + причина в `decisions.md`).
6. Итог дизайнеру: что есть, чего не хватает, что генерируем, вопросы заказчику
   (коротко, для мессенджера).

### 2. Тексты

1. Перенести тексты из `content-map.md` в `site/index.html` и
   `site/special-version/index.html`; контакты, адреса, реквизиты, ссылки, мета-теги
   (title, description, OG).
2. Прогнать `_typograf-site.js`, проверить локально (`node serve-site.js`), пуш.
3. Дать дизайнеру ссылку на превью для показа заказчику; правки — пакетом.

### 3. Промпты и визуал

1. Недостающее по айдентике — спросить (см. фазу 1, п. 4).
2. `/content-prompter`: `assets/prompts.md` — стилевой суффикс проекта + промпт
   на каждый слот со статусом «генерировать» (модель, формат, размер, имя файла).
3. Дизайнер генерирует в syntx.ai и кладёт исходники в `assets/raw/<slot-id>/`.
4. Claude готовит финальные файлы: кадрирование под размер слота, сжатие
   (фото — jpg/webp, видео — mp4 H.264 без звука, постер-кадр), запись в
   `site/assets/` под именем слота. Статусы слотов — в `content-map.md`.

### 4. Дизайн под заказчика (опционально)

Токены (цвета, шрифты, радиусы) в `site/css/tokens.css` и `themes.css`, логотип,
фавикон; при необходимости — правка/удаление блоков. Контраст — WCAG AA.

### 5. Вёрстка и адаптив (опционально)

Новые или изменённые блоки по правилам шаблона: те же брейкпоинты, поля через
переменные. Проверка на 375 / 768 / 1280 / 1440 и в версии для слабовидящих.

### Правка после вёрстки (в любой момент после фаз 4–5)

Поменялся UI-кит или макет в Figma, а сайт уже свёрстан → одна сессия, без
повторного прохода фаз 4 и 5: дизайнер называет изменённые компоненты/токены
(лучше ссылкой на фрейм), Claude читает только их через Figma MCP, правит код
и сразу проверяет адаптив. Подробно — `framework/04-frontend.md`,
«Правка после вёрстки».

### 6. Согласование и релиз

1. Чек-лист: noindex на всех страницах; формы и ссылки; контакты и реквизиты;
   юридические требования ниши (например, для медицины — предупреждение о
   противопоказаниях, лицензия); нет заглушек шаблона (поиск по имени прошлого
   клиента); вес страницы.
2. Заказчик согласовал превью → тег `vX.Y`, `gh release create` с `site.zip`
   (содержимое `site/`) и списком изменений.
3. Ссылку на релиз — дизайнеру для разработчика.

### 7. Инструкция по наполнению (PDF)

Для заказчика и для команды: как обновлять контент без Claude.
Собирается из `content-map.md` и `assets/prompts.md`. Содержание:

1. Как устроен сайт: папки, где лежат картинки, видео, тексты.
2. По каждому блоку: что изображено, модель (Nano Banana / Kling), шаблон промпта,
   формат и размер, имя файла, папка на ПК → путь на сайте.
3. Как подготовить файл (размер, сжатие, бесплатные инструменты).
4. Как поменять текст в `index.html` (найти, заменить, не трогать теги).
5. Как залить на хостинг и проверить результат.

Выход: `00-docs/Инструкция по наполнению.pdf`, копия — во вложения релиза.

### 8. Ретро и шаблон

1. `/retro` — уроки в `framework/lessons.md`.
2. Общие улучшения (не специфичные для клиента) — перенести в шаблон
   (`landing-template`); при первом проходе — выделить шаблон из Dental AI
   с учётом опыта проекта.
