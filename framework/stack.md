# Регламент выбора стека

Стек выбирается один раз — на разборе проекта — и фиксируется в `PROJECT.md`.
Менять посреди проекта нельзя без записи в `decisions.md` с причиной.

## Таблица решений

| Тип проекта | Стек | Хостинг | Когда отступить |
|---|---|---|---|
| Лендинг / промо (1–3 страницы) | HTML + CSS + JS + GSAP, без сборщиков | GitHub Pages / статик-хостинг | Нужна CMS для правок заказчиком → Astro + headless CMS |
| Корпсайт / многостраничник | Astro (+ GSAP для анимаций) | Netlify / Vercel (автодеплой из GitHub) | Меньше 4 страниц и нет переиспользуемых блоков → как лендинг |
| E-commerce: витрина (без корзины, заказ через форму/мессенджер) | Astro | Netlify / Vercel | — |
| E-commerce: полноценный магазин (корзина, оплата, ЛК) | Next.js + готовая e-com платформа по ситуации | Vercel | Заказчик уже на платформе (Shopify, InSales, Bitrix) → дизайн под неё, вёрстка в её шаблонах |

## Почему именно так

- **Чистый HTML для лендингов:** нулевая сложность, мгновенный старт, легко
  править точечно, идеально для GSAP-анимаций. Сборщик на 1–3 страницах —
  лишняя сущность.
- **Astro для многостраничников:** компоненты и переиспользование блоков
  (хедер/футер/карточки пишутся один раз), а на выходе — быстрая статика
  и SEO из коробки. Токен-экономия: правка компонента = правка одного файла.
- **Next.js только когда есть настоящая интерактивность** (корзина, авторизация,
  личный кабинет). Для статичных сайтов он избыточен: сложнее, дороже
  в поддержке, медленнее собирается.

## Фиксированные умолчания (для всех стеков)

Чтобы от проекта к проекту не «плавать»:

- **Стили:** чистый CSS с переменными-токенами из `ui-kit.md`. Без Tailwind и
  препроцессоров (в Astro/Next допустим CSS в компонентах). Методология
  классов — БЭМ-подобная, без фанатизма.
- **Анимации:** GSAP + ScrollTrigger. CSS-анимации — для простых ховеров
  и переходов.
- **Шрифты:** Google Fonts, подключение через `<link>` с preconnect; кириллица
  обязательна в выборе шрифта.
- **Иконки:** SVG инлайн или спрайт. Без иконочных шрифтов.
- **Изображения:** WebP (+ AVIF где просто), `loading="lazy"` ниже первого
  экрана, `srcset` для тяжёлых.
- **Git:** репозиторий с первого дня вёрстки, коммиты по блокам/страницам,
  ветки — только при параллельной работе.

## Вопросы разбора проекта, влияющие на стек

1. Сколько страниц и есть ли повторяющиеся блоки? → HTML или Astro.
2. Нужна ли корзина/оплата/ЛК? → Next.js или платформа заказчика.
3. Будет ли заказчик сам править контент? → нужна CMS (Astro + headless CMS,
   выбор конкретной — по ситуации на разборе проекта).
4. Где будет хоститься и есть ли ограничения (свой сервер, reg.ru и т.п.)?
