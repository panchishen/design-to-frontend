# Фаза 5. Релиз и Ретро

## Цель

Выложить сайт в прод, передать заказчику, извлечь уроки в фреймворк.

## Вход

- Фаза «Фронтенд» пройдена: чек-лист приёмки закрыт.

## Выход (артефакты)

- Сайт на проде, домен подключён. Репозиторий на GitHub.
- Ссылки (прод, репозиторий) в `PROJECT.md`, статус проекта — «сдан».
- Записи в `framework/lessons.md`, при необходимости — правки фреймворка.

---

## Сессия «Релиз»

Роли: Claude делает всё технически; Евгений — доступы (хостинг, домен) и команда
«выкладывай».

### Предрелизный чек-лист (выполняет Claude)

- [ ] Метатеги: title и description каждой страницы (из `content-map.md`),
      Open Graph (og:title, og:image), favicon.
- [ ] 404-страница в стиле сайта.
- [ ] Формы работают: отправка, валидация, сообщение об успехе, письмо/уведомление
      доходит (проверить реальный сабмит).
- [ ] Аналитика: Яндекс.Метрика / GA — код стоит, цели на целевые действия.
- [ ] robots.txt, sitemap.xml, канонические URL.
- [ ] Ссылки не битые, тексты финальные (сверка с `content-map.md`).
- [ ] Финальный прогон Lighthouse на проде.

### Деплой по типам (из stack.md)

- **Статика (HTML/GSAP):** GitHub Pages или любой статик-хостинг; деплой пушем
  в ветку / загрузкой сборки.
- **Astro:** Netlify или Vercel, автодеплой из GitHub-репозитория.
- **Next.js:** Vercel, автодеплой из GitHub.
- Домен и SSL: Claude даёт пошаговую инструкцию под конкретный хостинг,
  DNS-записи меняет Евгений (доступы у него).

### Стартовый промпт

```
Прочитай CLAUDE.md и PROJECT.md. Сессия «Релиз» по framework/05-release.md:
1) Прогони предрелизный чек-лист по 03-code/ и покажи отчёт.
2) Подготовь деплой по стеку проекта: репозиторий на GitHub, настройка
   хостинга. Скажи, какие доступы/действия нужны от меня.
3) После моего «выкладывай» — задеплой, проверь прод, обнови PROJECT.md.
```

## Сессия «Ретро» (~15 минут)

Роли: Claude ведёт разбор и вносит правки; Евгений отвечает на вопросы.

Вопросы ретро:

1. Где буксовали дольше всего? (фаза, тип задачи)
2. Какие правки заказчика повторялись — что не отловили на ранних гейтах?
3. Что в шаблонах/промптах фреймворка не сработало или мешало?
4. Что сработало отлично и стоит закрепить как правило?

Действия Claude по итогам:

- Записи в `framework/lessons.md` (формат — см. сам файл).
- **Правило двух повторов:** проблема встречается во втором проекте подряд →
  обязательная правка соответствующего файла фреймворка (шаблона, чек-листа,
  промпта), запись в `CHANGELOG.md`.
- Разовые уроки копятся в `lessons.md` — новые проекты наследуют их автоматически
  (CLAUDE.md шаблона велит читать lessons.md на триаже).

### Стартовый промпт

```
Прочитай CLAUDE.md, PROJECT.md и framework/lessons.md. Сессия «Ретро» по
framework/05-release.md: задай мне 4 вопроса ретро (по одному), затем:
запиши уроки в framework/lessons.md, проверь правило двух повторов —
если что-то повторилось, предложи конкретные правки файлов фреймворка
и после моего одобрения внеси их + запись в CHANGELOG.md.
```

## Гейт фазы (чек-лист)

- [ ] Предрелизный чек-лист закрыт, сайт на проде, домен работает.
- [ ] `PROJECT.md`: ссылки на прод и репозиторий, статус «сдан».
- [ ] Ретро проведено, уроки в `lessons.md`.

## Когда пропускать / упрощать

- Релиз не пропускается. Если хостинг заказчика экзотический — деплой руками
  Евгения по инструкции от Claude.
- Ретро можно упростить до 2 вопросов (1 и 3), но не пропускать: без него
  фреймворк не учится.
