# Фаза 3. Дизайн

## Цель

Превратить утверждённую контент-карту в макеты в Figma: прототип → UI-кит → макеты.
Смыслы уже зафиксированы, поэтому здесь решаются только вопросы формы.

## Вход

- `content-map.md` утверждён (или допущения зафиксированы).
- Визуальное направление выбрано.

## Выход (артефакты)

- Прототип (структурный wireframe) — утверждён.
- `02-design/ui-kit.md` — токены и компоненты, зеркало UI-кита в Figma.
- Макеты ключевых страниц в Figma — финализированы, ссылки в `PROJECT.md`.

## Правило маршрутизации правок (действует с этой фазы)

- **Правка смысла** (тексты, блоки, структура, оффер) → сначала `content-map.md`,
  потом макет. Если заказчик просит «поменять текст в макете» — это правка карты.
- **Правка визуала** (цвет, шрифт, композиция) → в макете; значимые решения
  фиксируются в `ui-kit.md`.

## Сессия «Прототип» (ч/б вайрфреймы)

Роли: Claude делает вайрфреймы полностью; Евгений ревьюит и затем дизайнит
поверх них — вайрфрейм является основой макета, а не черновиком «для понимания».

1. Claude из `content-map.md` строит **ч/б вайрфреймы** каждой страницы:
   для каждого блока — сетка, иерархия, положение и относительные размеры
   элементов, реальные тексты из контент-карты. Только оттенки серого,
   один системный шрифт, плейсхолдеры на месте контент-слотов (подписанные:
   какой слот, какой формат). Никакой стилистики — все визуальные решения
   остаются на фазу макетов.
2. Формат — два уровня, по ситуации:
   - **HTML-вайрфрейм** в `01-concept/prototype/` — кликабельный, быстро
     ревьюится в браузере, показывает и адаптивное поведение;
   - **Вайрфреймы в Figma** (через Figma MCP) — те же страницы кадрами
     в файле проекта, чтобы Евгений дизайнил прямо поверх них: слои-основа
     блокируются, дизайн собирается на их месте из UI-кита.
3. Евгений ревьюит раскладку. Правки — быстро, это дёшево.
4. Мягкий гейт: вайрфрейм можно показать заказчику («так будет устроена
   страница») — серый вид даже помогает: обсуждается структура, а не цвета.

### Стартовый промпт

```
Прочитай CLAUDE.md, PROJECT.md и 00-docs/content-map.md. Сессия «Прототип» по
framework/03-design.md: собери ч/б вайрфреймы всех страниц —
1) кликабельный HTML в 01-concept/prototype/ (оттенки серого, системный
   шрифт, реальные тексты, подписанные плейсхолдеры слотов), открой превью;
2) после моего ревью — перенеси вайрфреймы в Figma (Figma MCP), кадр на
   страницу, чтобы я дизайнил поверх.
```

## Сессия «UI-кит»

Роли: Claude предлагает систему токенов, Евгений утверждает и строит кит в Figma.

1. Claude из выбранного направления составляет `02-design/ui-kit.md`:
   - **Цвета:** основной, акцент, фоны, текст, статусы — HEX + роль каждого.
   - **Типографика:** пары шрифтов (с вариантами с Google Fonts), шкала размеров
     (H1–H4, body, caption) для десктопа и мобильных.
   - **Сетка и отступы:** контейнер, колонки, шкала отступов (8px-система).
   - **Компоненты:** кнопки (все состояния), поля, карточки, навигация — описание.
2. Евгений собирает UI-кит в Figma по этому документу (или корректирует документ
   под то, что получилось в Figma — документ и Figma должны совпадать).
3. При наличии Figma MCP: Claude может сгенерировать основу кита в Figma сам
   (переменные, стили, базовые компоненты) — Евгений дорабатывает.

### Стартовый промпт

```
Прочитай CLAUDE.md, PROJECT.md и выбранное направление в 01-concept/.
Сессия «UI-кит» по framework/03-design.md: составь 02-design/ui-kit.md —
цвета (HEX + роли), типографика (Google Fonts, шкала десктоп/мобайл),
сетка и отступы (8px), компоненты с состояниями. Если доступен Figma MCP —
предложи сгенерировать основу в Figma.
```

## Сессия «Макеты»

Роли: основную работу в Figma делает Евгений — это его зона мастерства.
Claude помогает: генерирует основу через Figma MCP, проверяет макеты на
соответствие контент-карте и UI-киту, готовит недостающий контент.

1. Порядок: главная (десктоп) → утверждение стиля на ней → остальные страницы.
2. Контент в макетах — только из `content-map.md`. Пустых слотов нет: для каждого
   контент-слота либо файл в `assets/`, либо задача в сессию Контент-промптер
   (см. `content-gen.md`).
3. Мягкий гейт: главная показывается заказчику до отрисовки остальных страниц.
4. Финал: ссылки на макеты — в `PROJECT.md`, статус фазы — «готово».

### Стартовый промпт

```
Прочитай CLAUDE.md, PROJECT.md, 00-docs/content-map.md и 02-design/ui-kit.md.
Сессия «Макеты» по framework/03-design.md. Задачи по ситуации:
- сгенерировать основу страницы в Figma по прототипу и UI-киту (Figma MCP);
- проверить готовый макет на соответствие контент-карте и UI-киту;
- составить список недостающего контента по слотам для Контент-промптера.
Начнём с: [что нужно]
```

## Гейт фазы (чек-лист)

- [ ] Прототип утверждён (Евгением, в идеале заказчиком).
- [ ] `ui-kit.md` совпадает с UI-китом в Figma.
- [ ] Макеты всех страниц готовы, контент — из контент-карты, слоты заполнены.
- [ ] Главная показана заказчику, реакция/допущения — в `decisions.md`.
- [ ] Ссылки на Figma — в `PROJECT.md`.

## Когда пропускать / упрощать

- **Лендинг из 4–6 блоков:** «Прототип» и «Макеты» можно слить в одну сессию,
  UI-кит — сократить до палитры, пары шрифтов и кнопок.
- **Редизайн с готовым фирстилем:** UI-кит строится из фирстиля за полсессии.
- Пропустить всю фазу нельзя — без макета нечего верстать. Исключение: прямой
  прототип-в-код для микропроектов (решение на триаже, причина в `decisions.md`).
