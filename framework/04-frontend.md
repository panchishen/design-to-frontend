# Фаза 4. Фронтенд

## Цель

Превратить макеты в живой сайт. Всю вёрстку делает Claude, Евгений ревьюит
результат в браузере как дизайнер: соответствие макету, типографика, отступы,
поведение анимаций.

## Вход

- Макеты финализированы, ссылки в `PROJECT.md`.
- Стек зафиксирован на разборе проекта (см. `stack.md`).
- Контент (фото, видео, тексты) собран в `assets/` и `content-map.md`.

## Выход (артефакты)

- Работающий сайт в `03-code/`: вёрстка, адаптив, анимации.
- Локальное превью для ревью. Git-репозиторий с историей коммитов.

## Порядок работы

**Десктоп → адаптив → анимации.** Не смешивать: сначала статичная десктопная
вёрстка всех страниц, потом адаптив, потом анимации. Так правки не каскадируют.

Это правило — для **первой сборки**. Правки дизайна после готовой вёрстки идут
по сессии «Правка после вёрстки» (ниже): вёрстка и адаптив — в одной сессии.

---

## Сессия «Вёрстка»

Роли: Claude верстает и держит превью открытым; Евгений ревьюит и даёт правки
списком.

1. Claude разворачивает проект в `03-code/` по стеку из `PROJECT.md`, `git init`.
2. Источник истины: макет в Figma (через Figma MCP — точные размеры, цвета,
   ассеты) + `ui-kit.md` (токены → CSS-переменные) + `content-map.md` (тексты).
3. Вёрстка постранично, блоками сверху вниз. После каждой страницы — коммит
   и ревью Евгения через превью.
4. Правки Евгений даёт списком («блок герой: заголовок меньше, отступ больше»),
   Claude вносит пакетом — так дешевле по токенам, чем по одной.

### Критерии приёмки вёрстки

- Визуальное соответствие макету (допуск ±2px на отступах, точные цвета/шрифты).
- Семантичная разметка (заголовки h1–h4 по иерархии, alt у изображений).
- Изображения оптимизированы (WebP/AVIF, lazy loading ниже первого экрана).
- Валидный HTML, без ошибок в консоли.

### Стартовый промпт

```
Прочитай CLAUDE.md, PROJECT.md, 02-design/ui-kit.md и 00-docs/content-map.md.
Сессия «Вёрстка» по framework/04-frontend.md: разверни проект в 03-code/
по стеку из PROJECT.md (git init, структура, токены из ui-kit.md как
CSS-переменные). Верстай десктоп постранично по макетам Figma [ссылка],
после каждой страницы — коммит и превью мне на ревью. Начни с главной.
```

## Сессия «Адаптив и анимации»

Роли: Claude делает, Евгений ревьюит на реальных ширинах.

### Адаптив

1. Брейкпоинты по умолчанию: 1440 (дизайн) / 1024 / 768 / 375.
2. Если мобильных макетов нет — Claude адаптирует сам по здравому смыслу
   и показывает Евгению спорные блоки (сложные сетки, таблицы, меню).
3. Проверка на каждом брейкпоинте: без горизонтального скролла, тексты читаемы,
   тап-зоны ≥ 44px, меню работает.

### Анимации

1. Уровень по умолчанию — «спокойный»: появление блоков при скролле (fade + сдвиг),
   ховеры, плавный скролл к якорям. GSAP + ScrollTrigger (или CSS, где хватает).
2. Более сложные анимации (параллакс, пиннинг, сторителлинг) — только если
   заложены в концепции.
3. `prefers-reduced-motion` обязателен. Анимации не блокируют чтение контента.

### Критерии приёмки фазы

- Lighthouse (мобайл): Performance ≥ 90, Accessibility ≥ 90, SEO ≥ 90.
- Кроссбраузерность: Chrome, Safari, Firefox, мобильный Safari/Chrome.
- 60fps на анимациях, нет layout shift (CLS < 0.1).

### Стартовый промпт

```
Прочитай CLAUDE.md и PROJECT.md. Сессия «Адаптив и анимации» по
framework/04-frontend.md: 1) адаптив всех страниц по брейкпоинтам
1024/768/375 — спорные блоки показывай мне; 2) анимации уровня «спокойный»
(скролл-появления, ховеры, prefers-reduced-motion). Затем прогони
чек-лист приёмки (Lighthouse, кроссбраузерность) и покажи отчёт.
```

## Сессия «Правка после вёрстки»

Когда: вёрстка и адаптив уже готовы, а в Figma поменялся UI-кит или макет.

1. Евгений называет, что изменилось: компоненты и/или токены (цвета, шрифты,
   отступы, радиусы), лучше со ссылкой на фрейм в Figma.
2. Claude через Figma MCP читает **только изменённое**, не весь кит.
3. Токены меняются в CSS-переменных (правка расходится по всему сайту),
   компоненты — в коде всех мест, где они используются.
4. Сразу проверка адаптива на всех брейкпоинтах и в версии для слабовидящих
   (если есть) — отдельная сессия адаптива не нужна.
5. Коммит, пуш на превью, итог Евгению: что поменялось и где.

Промпт: «Прочитай CLAUDE.md и PROJECT.md. Правка после вёрстки по
framework/04-frontend.md: в Figma изменилось [компоненты/токены, ссылка на фрейм].
Обнови код и сразу проверь адаптив на всех брейкпоинтах».

## Рефакторинг

Отдельная сессия нужна только если код вырос хаотично (много правок подряд).
Признаки: дублирующиеся стили, магические числа вместо токенов, копипаст блоков.
Промпт: «Прочитай CLAUDE.md. Отрефактори 03-code/ без изменения внешнего вида:
вынеси повторы, замени магические числа токенами. После — визуальная проверка
всех страниц на неизменность».

## Гейт фазы (чек-лист)

- [ ] Все страницы сверстаны и совпадают с макетами (ревью Евгения).
- [ ] Адаптив на 1024/768/375 проверен.
- [ ] Анимации работают, `prefers-reduced-motion` учтён.
- [ ] Lighthouse ≥ 90/90/90 (мобайл), консоль чистая.
- [ ] История коммитов осмысленная.

## Когда пропускать / упрощать

- Фаза не пропускается (это продукт). Упрощения: для внутренних/временных
  страниц можно снизить планку Lighthouse и сократить кроссбраузерную проверку —
  решение фиксируется в `decisions.md`.
