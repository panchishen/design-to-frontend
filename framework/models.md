# Модели по задачам и экономия токенов

## Модели Claude в Claude Code

Переключение: команда `/model` в сессии. Правило простое: **думает Opus,
делает Sonnet, рутину — Haiku.**

| Задача | Модель | Почему |
|---|---|---|
| Разбор проекта, разметка фаз | Opus | Решения, влияющие на весь проект |
| Исследование рынка, бриф | Opus | Синтез из разрозненных источников |
| Концепция: оффер, тексты, контент-карта | Opus | Качество формулировок = меньше правок |
| Прототип (HTML-wireframe) | Sonnet | Механическая сборка по готовой карте |
| UI-кит (документ токенов) | Sonnet | Структурированная работа по направлению |
| Вёрстка по макетам | Sonnet | Отлично верстает, дешевле Opus |
| Адаптив, анимации | Sonnet | Типовые паттерны |
| Сложный дебаг (анимация «прыгает», layout-баг) | Opus | Когда Sonnet застрял после 2 попыток |
| Рефакторинг | Sonnet | По чётким правилам из stack.md |
| Правки текстов, переименования, мелочь | Haiku | Скорость и цена |
| Релиз, деплой | Sonnet | Пошаговые операции |
| Ретро, правки фреймворка | Opus | Анализ и обобщение |
| Контент-промптер (промпты для syntx.ai) | Sonnet | Творческая, но шаблонная задача |

## syntx.ai — визуальный контент

Весь фото/видео/иллюстративный контент генерирует дизайнер в syntx.ai по промптам
из сессии «Контент-промптер» (см. `content-gen.md` — там же шпаргалка, какую
модель внутри syntx.ai выбирать под тип контента).

## Правила экономии токенов

1. **Состояние в файлах, не в чате.** Всё важное — в PROJECT.md, decisions.md
   и артефактах. Чат можно закрыть в любой момент без потерь.
2. **Сессия = фаза (или её кусок).** Не тянуть один чат через весь проект:
   длинный контекст = дорогие запросы и сжатие истории с потерей деталей.
3. **Точечный контекст.** В промпте указывать конкретные файлы, а не «посмотри
   проект». Стартовые промпты фаз уже так устроены.
4. **Правки пакетом.** Ревью — списком из 5–10 правок за раз, не по одной
   на сообщение.
5. **Не пересказывать.** Вместо пересказа макета/переписки — файл или ссылка
   (Figma MCP отдаёт данные макета напрямую).
6. **Планирование отдельно от исполнения.** Сложную задачу сначала спланировать
   (Opus), план — в файл, исполнять по плану (Sonnet) в новой сессии.
7. **Компактные артефакты.** Документы фреймворка — краткие, таблицами
   и списками: их читает каждая сессия, длина = постоянный налог.
