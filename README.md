# Фреймворк веб-проектов: дизайн → фронтенд

Система работы над проектами (лендинги, корпсайты, e-commerce) в связке
с Claude Code. Идея: **правда живёт в артефактах, а не в макете** — смыслы
утверждаются дёшево (текстами) до дорогих этапов (макеты, вёрстка).

Фреймворк упакован в плагин Claude Code **design-to-frontend**
(репозиторий — одновременно плагин и каталог плагинов `panchishen`).

## Установка (один раз)

1. Нужно приложение Claude (claude.ai/download) и Git (git-scm.com).
2. Скачай [`Установить фреймворк.cmd`](https://github.com/panchishen/design-to-frontend/blob/main/%D0%A3%D1%81%D1%82%D0%B0%D0%BD%D0%BE%D0%B2%D0%B8%D1%82%D1%8C%20%D1%84%D1%80%D0%B5%D0%B9%D0%BC%D0%B2%D0%BE%D1%80%D0%BA.cmd)
   (кнопка «Download raw file» справа над текстом) и запусти двойным кликом.
   Он проверит Claude Code (если нет — поставит), подключит каталог и установит
   плагин. Windows может предупредить о файле из интернета — «Подробнее» →
   «Выполнить в любом случае».
3. Перезапусти приложение Claude.

Вручную, в терминале:

```
claude plugin marketplace add panchishen/design-to-frontend
claude plugin install design-to-frontend@panchishen
```

## Быстрый старт нового проекта

1. Приложение Claude → вкладка **Code** → новая сессия в пустой папке проекта
   (например, `Сайт магазина игрушек`).
2. Набери `/new-project`. Claude предложит памятку по работе с Claude
   (`skills/new-project/memo.md`), создаст структуру из шаблона и спросит тип
   проекта: сайт с нуля или лендинг на шаблоне.
3. Дальше каждая фаза — новая сессия в папке проекта: `/next-phase` (сайт с нуля)
   или `/landing-next` (лендинг на шаблоне). В конце фазы Claude предлагает
   плашку на следующую.

## Карта сессий

Одна сессия Claude Code = одна фаза (или её кусок). Запуск — `/next-phase`:
команда сама берёт стартовый промпт сессии из файла фазы.

| # | Сессия | Промпт в файле | Модель |
|---|---|---|---|
| 1 | Разбор проекта | `framework/01-discovery.md` | Opus |
| 2 | Исследование | `framework/01-discovery.md` | Opus |
| 3 | Концепция | `framework/02-concept.md` | Opus |
| 4 | Прототип | `framework/03-design.md` | Sonnet |
| 5 | UI-кит | `framework/03-design.md` | Sonnet |
| 6 | Макеты | `framework/03-design.md` | Opus/Sonnet |
| 7 | Вёрстка | `framework/04-frontend.md` | Sonnet |
| 8 | Адаптив/анимации | `framework/04-frontend.md` | Sonnet |
| 9 | Релиз | `framework/05-release.md` | Sonnet |
| 10 | Ретро | `framework/05-release.md` | Opus |
| — | Контент-промптер (в любой момент) | `framework/content-gen.md` | Sonnet |
| — | Трек «Лендинг на шаблоне» (фазы 0–8, запуск `/landing-next`) | `framework/landing-track.md` | Opus/Sonnet |

Какие сессии нужны конкретному проекту — решает Разбор проекта (разметка фаз
в `PROJECT.md`). Ненужные пропускаются с записью причины в `decisions.md`.

## Как запускать сессии

При запуске сессии (или плашки) в Claude выбирается режим:

| Режим | Когда |
|---|---|
| **Start locally** | По умолчанию, почти всегда. Сессия работает прямо в папке проекта. |
| **Start with worktree** | Только если несколько сессий **одновременно** правят сайт. |
| Send to cloud | Не использовать: в облаке нет файлов с ПК. |
| Fix in this session | Не использовать: одна фаза — одна сессия. |

**Несколько сессий одновременно:**

- Каждую запускать через Start with worktree **из папки репозитория сайта**
  (например, `Лендинг`): у каждой сессии своя копия сайта в своей ветке.
- Закончил сессию — написать в ней «слей в main и запушь». Сливать по очереди.
- Параллелить только задачи в **разных блоках или файлах** (шапка / отзывы /
  токены цветов). Почти все стили лежат в одном `app.css`: одновременные правки
  одного блока дают конфликты при слиянии, а правка одной сессии может затереть
  другую.
- Правки одного блока (вёрстка → адаптив → дизайн) — последовательно, в одной
  сессии, пакетом.

**Поправил UI-кит в Figma, а сайт уже свёрстан:** одна сессия «Правка после
вёрстки» (`framework/04-frontend.md`). Назови, что изменилось (компоненты,
токены, ссылка на фрейм) — Claude обновит код и сразу проверит адаптив.
Отдельные сессии вёрстки и адаптива — только для первой сборки.

| `framework/01-discovery.md` … `05-release.md` | Фазы: шаги, чек-листы, промпты |
| `framework/stack.md` | Какой стек когда + фиксированные умолчания |
| `framework/models.md` | Какая модель для какой задачи, экономия токенов |

## Как фреймворк учится

1. После каждого проекта — сессия «Ретро» (~15 мин): уроки → `lessons.md`.
2. Новые проекты читают `lessons.md` на разборе проекта — опыт наследуется.
3. **Правило двух повторов:** проблема повторилась в двух проектах →
   обязательная правка шаблонов/чек-листов/промптов + запись в `CHANGELOG.md`.
4. Править фреймворк можно и напрямую: попроси Claude в сессии, открытой
   в папке фреймворка («добавь во фреймворк…») — правка + строка в `CHANGELOG.md`,
   дальше — см. «Обновление».

## Команды плагина

| Команда | Что делает |
|---|---|
| `/new-project` | Памятка (по желанию), проект из шаблона, выбор трека, разбор проекта |
| `/next-phase` | Следующая фаза полного цикла (или названная: «правка после вёрстки») |
| `/landing-next` | Следующая фаза трека «Лендинг на шаблоне» |
| `/project-status` | Где мы, последние решения, следующая фаза |
| `/content-prompter` | Промпты для syntx.ai по контент-слотам |
| `/retro` | Ретро: уроки в lessons.md, правки фреймворка (у владельца) |

Полное имя команды — `/design-to-frontend:<команда>`. Файлы скиллов — `skills/`;
пути к файлам фреймворка в них — через `${CLAUDE_PLUGIN_ROOT}` (корень плагина).

## Обновление

**Владелец (правит фреймворк):**

1. Правка в папке фреймворка на ПК — руками или попросив Claude в сессии,
   открытой в этой папке («добавь во фреймворк…»); `/retro` делает это сам.
2. Строка в `CHANGELOG.md`, коммит, `git push`.
3. У себя — запустить `Установить фреймворк.cmd` (обновит плагин) и
   перезапустить Claude. Плагин у всех, включая владельца, — копия с GitHub:
   неотправленные правки в папке в нём не появятся.

Версия плагина — коммит на GitHub (поле `version` в `plugin.json` не задано
намеренно): каждый пуш — новая версия, повышать номер не нужно.

**Команда:** запустить `Установить фреймворк.cmd` ещё раз и перезапустить
Claude — он обновит каталог и плагин. Чтобы обновления приходили сами:
в Claude Code `/plugin` → Marketplaces → `panchishen` → Enable auto-update.
Пожелания к фреймворку коллеги передают владельцу, уроки вносит он.
