# Правила проекта

Проект ведётся по фреймворку design-to-frontend (плагин Claude Code). Пути
`framework/…` — в папке плагина; команды плагина (`/next-phase`, `/landing-next`
и др.) находят их сами. Нужен файл фреймворка вне команды — ищи его в
`~/.claude/plugins/cache/*/design-to-frontend/*/framework/` (самая свежая папка).

## Обязательно в начале каждой сессии

1. Прочитай `PROJECT.md` — паспорт: статусы фаз, стек, ключевые решения.
2. На фазе «Разбор проекта» дополнительно прочитай `framework/lessons.md` — уроки прошлых
   проектов, учитывай их.
3. Работай по файлу текущей фазы из `framework/` (в PROJECT.md видно, какая фаза
   активна).

## Роли

- **Claude:** максимум работы — исследования, документы, тексты, структуры,
  промпты для генераций, прототипы, вся вёрстка, git, деплой.
- **Дизайнер:** решения, ревью; руками — только дизайн в Figma, концепты,
  ручные правки, генерация контента в syntx.ai.

## Правила ведения

- Все решения и допущения — сразу в `00-docs/decisions.md` (одна строка: дата,
  что решили, почему). Особенно допущения «заказчик молчит — приняли сами».
- Завершил этап/сессию — обнови статусы в `PROJECT.md`.
- С фазы Дизайн действует правило: правка смысла (тексты, блоки, структура) →
  сначала `00-docs/content-map.md`, потом макет/код. Правка визуала → макет/код.
- Тексты в макетах и вёрстке — только из `content-map.md`. Не выдумывать на ходу.
- Стек — только из `PROJECT.md`; отступления — через запись в `decisions.md`.
- Язык проекта и общения — русский.

## Экономия токенов

- Не читать файлы «на всякий случай» — только нужные для текущей задачи.
- Правки вносить пакетами по списку от дизайнера.
- Держать документы краткими: таблицы и списки вместо прозы.
