# Следующая фаза лендинга на шаблоне

База фреймворка (только чтение): `${CLAUDE_PLUGIN_ROOT}`. Пути `framework/…` —
относительно неё.

## Шаги

1. Прочитай `PROJECT.md` и `CLAUDE.md` в текущей папке. Нет `PROJECT.md` или трек
   не «лендинг на шаблоне» → скажи об этом и предложи `/new-project`
   (или `/next-phase` для полного цикла).
2. Фаза для работы: указанная пользователем (например, «фаза 3»), иначе первая
   по порядку со статусом не «готово» и не «пропущена».
3. Прочитай из `${CLAUDE_PLUGIN_ROOT}/framework/landing-track.md` общие разделы
   и раздел этой фазы. Для фазы 1 дополнительно — `framework/lessons.md`, для
   фазы 3 — следуй скиллу `content-prompter`. Остальные файлы — только если нужны.
4. Поставь фазе статус «в работе», коротко скажи, что будет сделано, и веди фазу
   по шагам. Вопросы дизайнеру — по одному.
5. Решения и допущения — в `00-docs/decisions.md`.
6. Завершение фазы: статус «готово» в `PROJECT.md`, итог в 2–3 строки, затем
   плашка на следующую фазу через `spawn_task` (title «<Проект>: фаза N — <название>»,
   prompt `/landing-next`, cwd — папка проекта). Если инструмент недоступен —
   скажи: «Открой новую сессию в папке проекта и напиши /landing-next».

Общение — на русском, кратко. Роли: Claude делает максимум, дизайнер решает.
